# 파일럿 피드백 (K-AIPA DQ)

채워서 `submission.json` 과 함께 보내 주세요. 이 양식과 모든 첨부·문의에는 **실제 환자 정보를 적지 않습니다.**

## 환자 정보 없이 쓰는 요령 (필수)

**적지 않는 것**: 환자 ID(`person_id` 등), 이름, 생년월일, 진료·검사·처방 날짜의 실제 값, 검사 수치와 코드값의 실제 값, 의무기록 문구, 위반 행의 값, 이런 값이 보이는 화면 캡처, 환자를 알아볼 수 있는 파일 이름·실행 이름. 값이 적은 작은 표에서 한 사람을 가리킬 수 있는 조합(희귀한 병기와 날짜 등)도 적지 않습니다. **`findings.csv` 와 오류 현황 CSV 는 첨부하지 않습니다.**

**적어도 되는 것**: 규칙 id, 표·컬럼 이름, 위반 **건수**, 병원이 값을 기록하는 **방식**(일반화한 설명), 필요한 코드의 **의미**.

| 이렇게 쓰지 말고 | 이렇게 씁니다 |
|---|---|
| `<환자 ID> 의 days_supply 가 <값> 인데 종료일이 <날짜> …` (실제 값을 넣은 서술) | `SEM-COM-005: 외래 처방의 days_supply 를 1회 수령량으로 적어 종료일 계산이 어긋난다` |
| `<날짜> 에 입력된 …` (실제 날짜를 넣은 서술) | `응급실 입력분에서만 반복된다` |
| 값이 보이는 화면 캡처 | 규칙 id 와 건수, 화면 이름만 |

정말로 값을 보여야 설명이 되는 경우는 먼저 파일럿 운영 측에 **값 없이 설명하는 방법**을 문의합니다. 값을 대신 보내도 된다는 안내는 이 양식에 없습니다.

## 규칙 이의

오탐이라고 보거나, 규칙이 병원 관행과 맞지 않거나, 뜻을 모르겠는 규칙을 적습니다. 많으면 `feedback_rules.csv` 에 표로 적어도 됩니다. 위의 요령대로 **값 없이** 적습니다.

| 규칙 ID | 판정 | 설명 (왜 그렇게 보는지, 병원에서는 어떻게 기록하는지) |
|---|---|---|
| 예: SEM-COM-005 | 오탐 | 외래 처방의 days_supply 를 1회 수령량으로 적어 약물 종료일 계산이 어긋난다 |
| | | |

판정은 셋 중 하나입니다.

- **오탐** — 데이터는 맞는데 규칙이 잘못 울린다.
- **정탐이지만 못 고침** — 규칙이 맞고 데이터 문제도 맞는데, 원천 시스템에서 고칠 수 없다(예: 과거 기록의 결측).
- **모르겠음** — 규칙의 뜻이나 조치 방법을 모르겠다.

기관의 판정은 **중앙이 이의를 검토할 때 참고하는 의견**입니다. 받아들일지는 중앙이 정하며([중앙 운영 절차](central-runbook.md)), 이 양식을 보냈다고 규칙이 바뀌지는 않습니다.
