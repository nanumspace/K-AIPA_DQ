# 4. 출력물 읽기와 제출

## 출력 파일 5종

실행마다 실행 폴더에 다섯 파일이 생깁니다.

| 파일 | 내용 | 외부 제출 |
|---|---|---|
| `report.md` | 검증 보고서. 요약, 분류별 집계, 실패 규칙과 예시, 입력 정규화. 규칙 설정을 바꿔 실행했다면 `## 규칙 설정` 절. 사람이 읽는 결과. **예시의 값은 가려져 있습니다** | 가능 |
| `findings.csv` | 위반 행 목록. 규칙, 테이블, 행 키, 환자 ID, 상세. 병원 안에서 데이터를 고칠 때 씁니다 | **금지** (환자 단위 정보) |
| `rule_results.csv` | 코호트에 적용된 규칙 전체의 통과·실패·건너뜀·꺼짐, 위반 수, 검사 행 수, 규칙 출처(`origin`: 표준·변경·사용자·관리자) | 가능 |
| `submission.json` | 중앙 제출용 집계. 환자 단위 정보를 뺀 규칙별 건수, 테이블 행 수, 입력 정규화 건수, 규칙 설정 요약(`rule_set`) | 가능. **병원 밖으로 보내는 유일한 파일** |
| `summary.json` | 엔진의 규칙 단위 원본 요약. 프로그램 간 비교용 | 가능 |

## 제출 규칙

- 중앙에 보내는 파일은 `submission.json` 하나입니다. 이 파일에는 규칙 id, 상태, 위반 건수, 테이블 행 수, 정규화 건수, 규칙 설정 요약만 있고 환자나 행 단위 정보는 없습니다.
- `findings.csv`는 환자 ID와 값이 들어 있으므로 병원 밖으로 내보내지 않습니다. 데이터 담당자가 원천 데이터를 고칠 때만 씁니다.
- **결과 폴더로 내보내기**로 만든 폴더에도 `findings.csv`가 들어 있습니다. 폴더째 보내지 말고 `submission.json`만 골라 보냅니다.
- 실행 이름(`label`)은 `submission.json` 에 그대로 실립니다. 환자를 알아볼 수 있는 말을 넣지 않습니다.
- 규칙 설정을 바꿨다면 `submission.json` 에 그 사실(`rule_set`)이 실립니다. 중앙은 표준 규칙만으로 실행한 결과와 따로 집계하므로 숨기지 말고 그대로 보냅니다. → [6. 규칙 편집](06-rules.md)

## 보고서 읽기

`report.md`와 **결과 보고서** 화면은 같은 내용을 보여 줍니다.

1. **요약**: 검사 행 수, 위반 건수, 오류율, 규칙 통과·실패·건너뜀 수.
2. **규칙 설정** (규칙 설정을 바꿔 실행했거나 관리자 모드를 쓴 경우에만): 표준 규칙 묶음 해시와 실제로 쓴 규칙 묶음 해시, 관리자 모드 사용 여부, 표준과 달라진 규칙의 표(규칙 id · 출처 · 변경 내용). 규칙 설정이지 환자 데이터가 아닙니다. 설정을 바꾸지 않았다면 이 절이 없습니다.
3. **분류별 집계**: 적합성(형식·코드·관계), 완전성(필수값), 타당성(범위·논리) 세 축의 위반 수.
4. **테이블 행 수**: 넣은 표별 행 수. 합쳐 읽은 표는 합친 뒤의 수입니다.
5. **실패 규칙과 예시**: 실패한 규칙마다 위반 수와 예시 두 개. 예시는 문장의 모양만 남기고 값(ID·날짜·수치·원천 문자열)을 `…` 로 가립니다 — 이 파일이 병원 밖으로 나갈 수 있기 때문입니다. 실제 값은 **오류 현황 조회** 화면이나 `findings.csv` 에서 봅니다.
6. **입력 정규화**: 검증 전에 걷어 낸 내보내기 흔적(`NULL` 글자, `.0`, `00:00:00`, 대소문자 컬럼명, 빈 끝 컬럼, 양끝 공백)의 표별 건수. 손댄 것이 없으면 이 절이 없습니다.

## 심각도와 조치

| 심각도 | 뜻 | 조치 |
|---|---|---|
| 오류 (error) | **매뉴얼에 적힌 것**의 위반: 표·컬럼 구성, 필수, 타입, PK/FK, 코드표, 매뉴얼이 정한 조건부 규칙(예: 매일 투여면 `days_supply` 필수) | 데이터 보완 또는 수정. 수정 후 제출 |
| 경고 (warning) | 매뉴얼 밖의 제약·임상 개연성: 임상 상식 범위, OMOP 대표 코드 집합, 명세에 없는 추가 컬럼, 병기군 표기(`LD`/`ED` 등), 항종양제의 `sact_id` 연결 확인 | 검토 후 맞으면 그대로 둠. 병원 코드나 관행 때문이면 파일럿 피드백으로 알림 |

오류율에 따른 상태 표시는 우수(1% 미만), 양호(1~2%), 주의(2~5%), 위험(5% 이상)입니다. 대시보드의 신호등이 이 기준을 따릅니다.

## 검사 유형별 조치 안내

**오류 현황 조회** 화면과 **검증 규칙 관리** 화면의 규칙 상세에서 같은 안내를 볼 수 있습니다.

| 검사 유형 | 뜻 | 조치 |
|---|---|---|
| 테이블 누락 | 필요한 표 파일이 없음 | 코호트 구성에 맞는 파일을 모두 제출. 사례가 없으면 헤더만 있는 파일 |
| 컬럼 누락 | 매뉴얼의 컬럼이 파일에 없음 | 컬럼명을 명세에 맞춤. 컬럼 명세서 참고 |
| 명세 외 컬럼 (경고) | 매뉴얼에 없는 컬럼이 파일에 있음 | 검사에는 쓰이지 않음. 필요 없으면 뺌 |
| 키 중복·누락 | 기본키가 비었거나 중복 | 행 식별자를 고유하게 부여. 두 폴더를 합쳐 읽을 때 같은 행이 두 번 있는지 확인 |
| 필수값 누락 | 필수 항목이 비어 있음 | 원천 시스템에서 값을 보완 |
| 데이터 타입 불일치 | 값의 형식이 명세와 다름 | 날짜는 YYYY-MM-DD, 숫자는 숫자만 |
| 코드표 밖 값 | 코드 컬럼이 매뉴얼의 코드 목록에 없음 (OMOP 대표 코드 집합이면 경고) | `1`·`0`·`9` 처럼 목록의 코드를 그대로. 병원 코드가 맞다면 경고는 규칙 설정에서 허용 코드를 추가 |
| 범위 밖 값 (경고) | 임상 상식 범위를 벗어남 | 입력 오류인지 확인. 실제 값이 맞으면 규칙 설정에서 범위를 조정 |
| 관계 무결성 오류 | 참조하는 행이 없음 (예: DRUG_EXPOSURE 의 `sact_id` 가 SACT 에 없음) | 참조 표의 누락 행을 함께 제출 |
| 비항암 코호트의 `sact_id` | SACT 가 없는 코호트(대사이상지방간·당뇨병)에서 `sact_id` 를 적음 | 비워 둠 |
| 미래 날짜 | 검증 실행일 이후 날짜 | 입력 오류인지 확인. 검증 실행일을 추출일로 맞춤 |
| 논리·교차 검증 | 표 간 논리 불일치 (사망 뒤 사건, 방문 기간 밖 사건, 약물 종료일과 `days_supply` 등) | 상세 내용의 날짜·값 관계를 확인 |

## 위반 행 찾기

**오류 현황 조회** 화면에서 실행을 고르고 규칙, 테이블, 심각도, 검색어로 걸러 위반 행을 봅니다. 각 행에는 테이블, 행 키, 환자 ID, 상세 설명이 있어 원천 데이터에서 바로 찾을 수 있습니다. 걸러진 목록은 CSV로 내보낼 수 있습니다. 이 CSV 역시 환자 단위 정보이므로 병원 밖으로 보내지 않습니다. 위반 행은 원천 표에서 직접 고칩니다.
