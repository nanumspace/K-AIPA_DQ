# K-AIPA DQ 사용자 설명서

**K-AIPA DQ**(K-AIPA 임상 데이터 품질검증, K-AIPA Clinical Data Quality Validator) 버전 1.0.7 의 사용자 설명서입니다. 병원 담당자가 코호트 데이터를 제출하기 전에 스스로 품질을 점검하는 프로그램입니다. 코호트 테이블 파일(질환 본표와 환자·방문·약물·검사 등 공통 표)을 넣고 실행하면 의뢰사 매뉴얼(2026-11-16) 기반 검증 규칙 437개(코호트마다 299~340개가 적용)를 검사해 보고서를 만듭니다.

## 이 프로그램이 하는 일과 하지 않는 일

[K-AIPA](https://k-aipa.org/overview)는 K-AI 신약개발의 전임상·임상 모델개발을 다루는 사업입니다. 이 프로그램은 그중 **여섯 질환(폐암·유방암·대장암·대사이상지방간·당뇨병·림프종) 임상 코호트 테이블이 매뉴얼 명세에 맞는지 점검하는 일**만 합니다.

| 하는 일 | 하지 않는 일 |
|---|---|
| 표 형식, 필수값, 코드표, 날짜 순서, 표 사이 연결, 임상 상식 범위를 규칙으로 점검 | 전임상 데이터, 오믹스 데이터, AI 모델의 검증 |
| 위반 건수와 규칙별 결과를 보고서로 정리 | 임상적 적절성의 판정, 임상 데이터 인증, 제출 승인·접수 결정 |

이 문서와 프로그램은 K-AIPA 의 공식 승인이나 후원을 받았다고 주장하지 않으며, K-AIPA 로고·명칭의 사용 허락을 받았다는 뜻도 아닙니다. 보고서의 건수·등급은 이 프로그램의 규칙을 기준으로 한 점검 결과이며 공식 합격·불합격 판정이 아닙니다.

## 먼저 알아 둘 것

- **병원 데이터베이스에 접속하지 않습니다.** 내보낸 파일만 읽습니다.
- **프로그램에는 데이터를 외부로 자동 전송하거나 업로드하는 기능이 없습니다.** 실행 이력과 결과 파일은 이 컴퓨터의 앱 데이터 폴더에만 저장됩니다. 다만 사용자가 **내보내기**나 **다른 이름으로 저장**으로 파일을 복사하거나 직접 전달하면 그 파일은 프로그램 밖으로 나갑니다. 그 파일에 환자 단위 정보가 들어 있는지는 파일마다 다릅니다([4장](04-output.md)의 파일 분류).
- 환자 ID 와 값이 들어 있는 파일(`findings.csv`, 오류 현황에서 내보낸 CSV, 실행 폴더의 `input/`)은 **기관 내부 전용**입니다. 중앙에 보내는 파일은 집계 파일 `submission.json` 이며, **보내기 전에 기관이 내용을 확인합니다**.
- 위반 0건은 이 프로그램의 규칙을 어기지 않았다는 뜻일 뿐, 임상적 적절성이나 승인을 뜻하지 않습니다. 규칙이 **건너뜀·오류·꺼짐**이었다면 그 규칙은 통과한 것이 아닙니다([4장](04-output.md)).

## 데이터가 오가는 길

```
코호트 테이블 (PERSON · VISIT_OCCURRENCE · … · 질환 본표 · SACT …)  ──→  검증 실행  →  보고서 · submission.json 등 결과 파일
  병원이 매뉴얼 양식에 맞춰 직접 채움 (CSV · 엑셀 · 폴더)                      (이 PC 의 앱 데이터 폴더에 저장)
```

병원은 **표를 직접 채웁니다.** 코호트마다 질환 본표 하나와 OMOP 형식 공통 표(PERSON, VISIT_OCCURRENCE, PROCEDURE_OCCURRENCE, DRUG_EXPOSURE, CONDITION_OCCURRENCE, MEASUREMENT, OBSERVATION, NOTE), ADVERSE_EVENT, 항암요법 SACT(폐암·유방암·대장암·림프종)를 만들어 **검증 실행** 화면에 넣습니다.

| 3 | [검증 실행](03-run.md) | 코호트 선택, 파일 넣기, 테이블 대응 확인, 실행 |

## 검증 기준

검증 기준은 하나입니다. 의뢰사 **「질환별 데이터 테이블」 매뉴얼 2026-11-16** 이며 표 16개 · 필드 157개(매뉴얼) + 보완 선택 컬럼 6개·선택 테이블 2개, 규칙 437개(구조 410 + 교차 27)입니다. 매뉴얼에 적힌 것의 위반은 **오류**, 임상 상식 범위나 OMOP 대표 코드 같은 매뉴얼 밖 제약의 위반은 **경고**로 표시합니다([4장](04-output.md)). 규칙의 구성은 [docs/spec-and-rules.md](../docs/spec-and-rules.md)에 있습니다.

내부 폴더·파일·앱 데이터 폴더 이름 일부(`kai_cdm_spec.yaml`, `kai-dq-submission/3` 스키마 이름, 앱 데이터 폴더 `Quality Validator` 등)는 기존 설치와 파일 형식의 연속성을 위해 옛 이름을 유지합니다.
