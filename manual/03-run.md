# 3. 검증 실행

채운 테이블 파일을 바로 **검증 실행** 화면에 넣으면 됩니다.

## 검증 실행

**검증 실행** 화면은 위에서 아래로 네 단계입니다.

### ① 코호트와 파일

1. **코호트**를 고릅니다 (폐암, 유방암, 대장암, 대사이상지방간, 당뇨병, 림프종). 필요한 표(폐암·유방암·대장암·림프종 11개, 대사이상지방간·당뇨병 10개)가 아래에 나열됩니다. 이 프로그램이 다루는 코호트는 이 여섯 가지뿐입니다.
2. 파일을 넣습니다. 세 가지 방법이 있습니다.
   - 파일이나 폴더를 창 안의 점선 영역에 **끌어다 놓기**
   - **파일 선택**으로 CSV 여러 개 또는 엑셀 한 파일 고르기
   - **폴더 선택**으로 폴더 고르기 (여러 개도 가능)

폴더를 여럿 넣으면 파일 목록 위에 폴더 칩(`추출본 · 11개 ×`)이 서고, × 로 그 폴더에서 온 파일을 한꺼번에 뺄 수 있습니다. 파일마다 어느 폴더에서 왔는지 이름 아래에 적힙니다.

### ② 테이블 대응과 사전 점검

파일을 넣으면 대응표가 나타납니다. 왼쪽이 코호트에 필요한 표, 오른쪽이 프로그램이 골라 놓은 파일(또는 시트)입니다.

- 자동 대응이 틀렸으면 오른쪽 드롭다운에서 다른 파일을 고릅니다.
- 같은 이름의 파일이 두 폴더에서 오면 합쳐 읽는다고 표시됩니다(`MEASUREMENT.csv (폴더 A) + MEASUREMENT.csv (폴더 B) (합침)`). 하나만 쓰려면 드롭다운에서 그 파일을 고릅니다.
- **미리보기**로 앞부분 몇 줄을 확인할 수 있습니다.

사전 점검 결과가 함께 표시됩니다.

| 표시 | 뜻 | 실행 |
|---|---|---|
| 오류 | PERSON 이나 질환 본표가 없음, 기본키나 person_id 컬럼이 없음, 파일을 읽을 수 없음(빈 파일·알 수 없는 인코딩), 중복된 컬럼명 | 차단됨. 먼저 해결해야 합니다 |
| 주의 | 표가 없음(빈 파일이라도 넣기를 권함), 명세와 다른 컬럼, 날짜 형식이 다른 표본, 합치는 파일들의 컬럼 구성이 다름 | 가능하지만 결과에 위반으로 나타날 수 있습니다 |
| 참고 | 대소문자 컬럼명, `NULL` 글자, `.0`, `00:00:00`, 구분자, 파일 합침 | 알아서 처리됩니다. 무엇을 했는지 보고서에 적힙니다 |

### ③ 실행

**실행 이름**을 적고(예: `2026-09 제출본`. 비우면 입력 파일이 든 폴더 이름), **검증 실행일**을 확인한 뒤 **검증 실행**을 누릅니다. 이 날짜 이후의 날짜는 "미래 날짜"로 판정됩니다. 기본값은 오늘이며 **설정**에서 바꿀 수 있습니다. 데이터를 뽑은 날로 맞추는 것이 좋습니다.

**실행 이름은 `submission.json` 의 `label` 에 그대로 실립니다.** 비워 두면 입력 폴더 이름이 쓰이는데, 폴더 이름에 환자나 병원 내부 식별 정보가 있으면 그대로 실립니다. 환자를 알아볼 수 있는 말은 넣지 않습니다.

진행률이 표시되며 화면은 그동안 계속 쓸 수 있습니다. 환자 100명 규모는 수 초, 2,000명(행 50만) 규모도 10초 안팎입니다.

넣은 파일은 이 PC 의 앱 데이터 폴더 아래 실행 폴더(`runs/<실행 ID>/`)의 `input/` 안에 `<TABLE>.csv`(UTF-8, 쉼표 구분, 명세 컬럼명)로 정규화되어 **사본**이 보관됩니다. 원본 파일은 바뀌지 않습니다. 이 사본에는 환자 단위 정보가 그대로 들어 있습니다. 위치와 삭제 방법은 [1장](01-install.md)을 봅니다.

규칙 설정을 바꿨다면(켜고 끄기, 범위 조정, 추가한 규칙) 그 설정으로 실행되고, 결과에 표준과 다르게 실행했다는 사실이 남습니다. → [6. 규칙 편집](06-rules.md)

### ④ 결과와 출력물

실행이 끝나면 요약이 나옵니다. 화면과 일부 이전 판에서 이름이 조금씩 다르므로 정확한 정의를 적습니다.

| 항목 | 정확한 뜻 |
|---|---|
| 입력 행 수 (화면에서 "검사 행 수", 대시보드에서 "데이터 건수") | 넣은 **표들의 행 수 합계**. 규칙마다 검사한 행의 합이 아니며, 환자 수도 아닙니다 |
| 위반 건수 | 규칙에 걸린 **(규칙, 행) 쌍의 총수**. 오류와 경고를 **모두** 합친 값이고, 오류·경고 내역이 아래에 따로 표시됩니다 |
| 위반율 (이전 판에서 "오류율") | 위반 건수 ÷ 입력 행 수. 한 행이 여러 규칙을 어기면 그만큼 중복으로 세므로 **오류가 있는 환자나 행의 비율이 아닙니다.** 100%를 넘을 수도 있습니다 |
| 실행 규칙 / 실패 / 건너뜀 / 꺼짐 | 규칙 단위 상태. 아래 표를 봅니다 |

**규칙별 비율은 따로 봅니다.** 규칙마다 위반 수와 그 규칙이 검사한 행 수(`rows_checked`)가 `rule_results.csv` 에 있으므로, 규칙별 위반율은 그 둘로 계산합니다. 전체 위반율과 규칙별 위반율은 분모가 달라 서로 맞춰 볼 수 없습니다. 상세와 해석은 [4장](04-output.md)에 있습니다.

규칙 상태는 다섯 가지이며 **통과(pass)만 "검사했고 위반이 없다"는 뜻입니다.**

| 상태 | 뜻 | 통과인가 |
|---|---|---|
| 통과 (pass) | 규칙을 실행했고 위반 0건 | 예 |
| 실패 (fail) | 규칙을 실행했고 위반이 있음 | 아니오 |
| 건너뜀 (skipped) | 필요한 표가 없어 실행하지 못함 | **아니오.** 검사하지 않은 것 |
| 오류 (error) | 규칙 실행 중 오류가 남 | **아니오.** 검사하지 못한 것. 위반 건수는 0으로 보이지만 결과를 믿을 수 없음 |
| 꺼짐 (disabled) | 사용자가 규칙을 껐음 | **아니오.** 검사하지 않은 것 |

위반 0건이라도 건너뜀·오류·꺼짐 규칙이 있으면 그 규칙의 항목은 확인된 것이 아닙니다.

아래에 출력물 5종이 나열되며, 각 파일을 바로 열거나 **실행 폴더 열기**로 폴더를 볼 수 있습니다. 파일마다 **다른 이름으로 저장**이 있고, **결과 폴더로 내보내기 (전체)**를 누르면 다섯 파일과 안내 README를 원하는 폴더 하나에 담아 줍니다. 두 방법 모두 이 PC 안에서 파일을 복사할 뿐 전송하지 않지만, **복사한 파일은 앱의 통제 밖**이므로 내보내기 전체에는 `findings.csv` 가 들어 있다는 점에 주의합니다. 파일별 내용과 공유 규칙은 [4. 출력물 읽기와 제출](04-output.md)에 있습니다.

## 다시 실행하기

데이터를 고친 뒤 같은 코호트로 다시 실행하면 새 실행으로 기록됩니다. 이전 실행과의 위반 건수 변화는 **통계 모니터링** 화면에서 추이로 볼 수 있습니다. 필요 없는 실행 기록은 같은 화면에서 지울 수 있으며, 지워도 이미 내보낸 사본은 남습니다([1장](01-install.md)의 "백업과 삭제").

**대시보드의 "질환별 최신 결과"는 코호트마다 가장 최근 실행 하나**만 보여 줍니다. 규칙 설정을 바꾼 실행이 가장 최근이면 그 결과가 보입니다. 어떤 설정으로 돌렸는지는 **결과 보고서** 화면 위쪽의 안내(표준과 다른 규칙 설정 · 관리자 SQL 포함)와 `report.md` 의 `## 규칙 설정` 절에서 확인합니다.
