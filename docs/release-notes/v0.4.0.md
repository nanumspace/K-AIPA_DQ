### 바뀐 점

- **새 기준은 의뢰사 매뉴얼 2026-11-16 하나입니다.** 표 16개 · 필드 157개, 규칙 390개(구조 368 + 교차 22)이며 코호트마다 253~294개가 적용됩니다(폐암 285 · 유방암 294 · 대장암 277 · 대사이상지방간 257 · 당뇨병 253 · 림프종 286). 매뉴얼에 적힌 것의 위반은 오류, 임상 상식 범위·OMOP 대표 코드 같은 매뉴얼 밖 제약의 위반은 경고입니다. 매뉴얼에 없는 표·열은 만들지 않으며, 명세에 없는 열이 파일에 있으면 경고만 합니다.
- **이전 기준을 제거했습니다.** 이전 명세 3종과 기준 전환 기능, 서식을 채워 변환하는 단계, 매뉴얼 수정 제안 검토 서비스를 모두 없앴습니다. 이전 기준으로 검증하려면 이전 버전 앱(v0.3.x)을 쓰세요. 설정에서 고르는 기준은 더 이상 없습니다.
- **규칙을 편집할 수 있습니다.** **검증 규칙 관리**에서 규칙을 켜고 끄기(수준 1), 심각도와 값 범위·정규식·허용 코드 조정(수준 2), 양식으로 사용자 규칙(`USR-###`) 추가(수준 3). **설정의 관리자 모드**(비밀번호 없음)에서는 교차 규칙의 SQL 수정과 SQL 규칙(`ADM-###`) 추가(수준 4). 표준과 다르게 실행하면 `report.md` 의 `## 규칙 설정`, `rule_results.csv` 의 `origin` 열, `submission.json` 의 `rule_set`(표준·실제 규칙 묶음 해시, 관리자 모드, 꺼진·바꾼·사용자·관리자 규칙)에 기록되고, 설정 변경 이력이 앱 데이터 폴더에 남습니다. 중앙은 표준이 아닌 규칙의 결과를 기관 간 비교와 따로 집계합니다. → [규칙 편집](https://github.com/nanumspace/KAI_DQ_App/blob/main/manual/06-rules.md)
- **매뉴얼 해석을 명시했습니다.**
  - NOTE 의 필수는 `note_id`, `note_type_concept_id`, `note_class_concept_id` 뿐입니다.
  - 약물의 화학 구조식(SMILES)은 NOTE 레코드로 두고 `DRUG_EXPOSURE.note_id` 가 가리킵니다. 견본 데이터는 `note_class_concept_id` 를 0 으로 둡니다. `sact_id` 와 `note_id` 는 선택입니다.
  - 림프종 `cell_of_origin` 은 필수이고 DLBCL 이 아니면 `NA` 입니다. 입력 정규화는 `NA` 글자를 빈 값으로 읽지만 **이 열에서만 `NA` 를 그대로 둡니다.**
  - 폐암 `clinical_stage` 는 AJCC 병기군입니다. 소세포폐암의 제한기/확장기(LD/ED)는 경고하며 TNM 병기로 바꿔 입력해야 합니다.
  - `diag_rgst_ymd` 는 진단일이 아니라 진단정보 등록일입니다.
  - 투여 빈도가 있으면 `days_supply`, 투여 간격이 1일을 넘으면 `dosing_number` 가 필수이며 위반은 오류입니다.
- 견본 데이터 zip 은 새 기준의 가상데이터(clean · dirty · good)입니다. dirty 의 오류는 규칙에서 역으로 만든 것이라 «모두 검출»이 실제 병원 데이터에서의 민감도는 아니며, Good Sample 은 합성한 자료로 임상의의 감수를 받지 않았습니다.
- **검토에서 발견한 문제 6건을 수정했습니다.**
  - 관리자 모드를 끄거나 앱을 다시 열어도 저장한 SQL 규칙은 실행합니다. 편집 모드 상태와 관리자 변경 규칙 사용 여부는 별도로 기록합니다.
  - 외부용 보고서에서 입력 원문 예시를 제외하고, 요약·규칙별 CSV에서도 DB 오류 원문을 제외합니다. 내부 진단과 `findings.csv` 는 외부로 보내지 않습니다.
  - 정규화 후 중복 열과 잘리거나 버려질 CSV 값을 전체 파일에서 검사합니다. 문제 파일·행을 알리고 실행 직전에도 다시 차단합니다.
  - 치료 차수의 연속성·순서 확인은 `SEM-SACT-006` 경고로 분리합니다. 날짜 역전은 `SEM-SACT-001` 오류로 유지합니다.
  - 관리자 SQL 반환 열은 0행이어도 이름·개수를 검사하고 순서와 무관하게 이름으로 연결합니다.
  - 규칙 해시에 명세·허용 코드 값·보조 concept·코호트 구성을 포함합니다. 이전 해시와는 직접 비교하지 말고 같은 기준으로 다시 검증하세요.

### 알려진 한계

- Athena 어휘가 들어 있지 않아 concept_id 의 존재·표준 여부는 검사하지 않습니다(OMOP 코드표는 경고 수준).
- 항종양제 판정(`sact_id` 연결 확인)은 앱에 내장된 항암제 목록을 기준으로 하므로 목록 밖 약제는 잡지 못합니다.
- 림프종 아형(DLBCL 여부)을 담은 열이 명세에 없어, DLBCL 인데 `cell_of_origin` 에 `NA` 를 잘못 적은 경우(또는 그 반대)는 검출하지 못합니다.
