## 변경 사항

표준 용어 방침의 남은 결정 세 가지를 확정해 반영했습니다([docs/vocabulary.md](https://github.com/nanumspace/K-AIPA_DQ/blob/v1.0.3/docs/vocabulary.md) 4절). 셋 다 **매뉴얼 보완**이며, 기존 병원 데이터는 이전과 같은 결과를 얻습니다(새 규칙은 모두 경고이고, 선택 항목을 내지 않으면 건너뜁니다).

- **원천 코드 선택 컬럼:** CONDITION_OCCURRENCE·PROCEDURE_OCCURRENCE·DRUG_EXPOSURE 끝에 `*_source_value`(병원 원천 코드, 예 KCD-8·EDI)와 `*_source_concept_id`(그 원천 개념 ID)를 넣을 수 있습니다. 매뉴얼 1.2 ⑦ "원본 코드 유지"를 따르기 위한 것입니다. 없어도 '컬럼 누락'이 아니고 사전 점검은 안내만 냅니다.
- **표준 용어 선택 테이블:** 병원이 쓴 개념만 담은 **CONCEPT** 일부와 **VOCABULARY** 를 함께 낼 수 있습니다. 내면 개념 필드 25개마다 개념 존재, 표준·유효 여부, 영역, 허용 어휘를 보고(`표준 용어` 규칙, 경고), VOCABULARY 의 배포판이 v20260829(`v5.0 29-AUG-26`)인지 봅니다(`SEM-VOC-001`, 경고). 원천 개념은 존재만 봅니다. 앱에 어휘를 넣지 않으므로 어휘 재배포 문제가 없습니다. 추출 방법은 [manual/02-input.md](https://github.com/nanumspace/K-AIPA_DQ/blob/v1.0.3/manual/02-input.md) 에 있습니다.
- **이상사례 코드값 표기:** ADVERSE_EVENT 의 `severity`·`causality`·`seriousness`·`outcome`·`action_taken` `_concept_id` 는 컬럼 이름을 그대로 두고, 명세 설명·입력 양식·컬럼 명세서·자료실에 "매뉴얼 자체 코드값, OMOP 표준 개념 ID 아님"을 적었습니다. 코드표 이름은 `OMOP.*` 에서 `AE.severity`·`AE.causality`·`AE.seriousness`·`AE.outcome`·`AE.action_taken` 으로 바꿨습니다. 코드값과 심각도는 그대로입니다.
- **규칙 수:** 433개(구조 410 + 교차 23). 매뉴얼 규칙 ST-0001~ST-0368 의 번호는 그대로이고, 보완 규칙은 ST-0369~ST-0410 과 SEM-VOC-001 입니다. 기관의 규칙 조정은 그대로 남습니다.
- **입력 양식·컬럼 명세서:** 선택 표 CONCEPT·VOCABULARY 시트(CSV)와 '구분' 열(매뉴얼 / 보완 · 선택 컬럼 / 보완 · 선택 테이블)이 추가되었습니다.
- **검증 기준 패키지 1.0.3:** 새 검사 유형(`concept`)과 선택 표를 쓰므로 **앱 1.0.3 이상**이 필요합니다.

## 그대로인 것

- 매뉴얼 **2026-11-16** 의 16개 테이블·157개 컬럼과 그 규칙 368 + 교차 22 의 판정 방식과 심각도.
- 견본 데이터(clean·dirty·Good Sample)의 내용. 견본에는 선택 컬럼과 선택 표를 넣지 않으므로 표준 용어 규칙은 '건너뜀'으로 나옵니다.
- 6개 코호트 모두 주입 오류 100% 검출, clean·Good Sample 오류 0건.

## 한계

선택 표 CONCEPT 를 내지 않으면 개념 ID 의 어휘 존재·표준 여부는 검사하지 않습니다. CONCEPT 를 내더라도 그 내용이 실제 Athena 배포판과 같은지는 앱이 확인할 수 없습니다. 개념 ID `0`(매핑 실패) 비율 지표는 아직 없습니다.
