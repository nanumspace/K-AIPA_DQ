## 변경 사항

- **데이터 충실도 (새 기능):** 규칙이 보는 "있는 행이 맞게 적혔는가"와 별개로, 지침에 근거해 **있어야 할 기록이 실제로 있는가**를 셉니다. 6개 코호트에 22개 항목(공통 5: 키·체중·항암 전 키·체중·요법별 ECOG·항암 전 혈구검사, 폐암 EGFR·ALK·흉부 CT, 유방암 HER2·ER·PR·병기, 대장암 MMR/MSI·CEA·전이성 RAS, MASLD FIB-4 구성 검사와 반복·연 1회 체중, 당뇨병 HbA1c 진단 시·6개월마다·연 1회 혈압·신기능·지질·체중, 림프종 LDH·IPI 구성요소·PET-CT 또는 골수 생검)이 있습니다. 근거와 결정은 [docs/data-sufficiency.md](https://github.com/nanumspace/K-AIPA_DQ/blob/v1.0.4/docs/data-sufficiency.md)에 있습니다.
  - 결과는 **비율만** 보입니다. 충족 판정·목표치가 없고 오류·경고 건수와 규칙 통과율에 들어가지 않습니다. 기록이 없는 원인(미시행·외부 시행·추출 누락·매핑 차이)은 단정하지 않습니다.
  - 보고서(`report.md`)에 '데이터 충실도' 절, 결과 보고서 화면에 같은 카드가 생겼습니다. 항목별 대상·충족 수, 비율, 1인·1년당 횟수 중앙값, 연령대별 충족/대상을 보입니다.
  - 새 출력 `sufficiency.csv` 에 미충족 환자·요법과 사유가 있습니다. **환자 단위 정보라 기관 내부 전용**입니다.
  - `submission.json` 은 스키마 `kai-dq-submission/3` 이며 항목별 집계(`sufficiency`)가 들어갑니다. 환자 단위 값은 없습니다. 중앙 집계 도구(`pilot/aggregate.py`)가 `sufficiency_by_site.csv` 를 만듭니다.
- **바이오마커·병기는 MEASUREMENT 의 LOINC 검사로:** 질환 본표에 필드가 없는 EGFR·ALK, HER2, ER·PR, 유방암 병기, MMR/MSI, RAS 는 MEASUREMENT 행으로 적습니다. 결과는 `value_as_concept_id` 나 `value_as_number` 에 둡니다. 적는 법은 [manual/02-input.md](https://github.com/nanumspace/K-AIPA_DQ/blob/v1.0.4/manual/02-input.md)에 있습니다.
- **개념 집합:** 검사·시술은 대표 개념을 기준 어휘 v20260829 로 펼친 표준 개념 ID 목록(같은 LOINC 구성요소·검체의 모든 검사, SNOMED 하위 개념)으로 셉니다. 기준 패키지의 `spec/concept_sets.yaml` 에 ID 만 들어 있어 병원이 따로 낼 것은 없습니다.
- **견본 데이터:** 폐암 EGFR·ALK, 유방암 ER·PR·HER2·병기군, 대장암 MSI·KRAS·NRAS 결과를 MEASUREMENT 행으로 더했습니다(판독 NOTE 와 같은 값). 견본의 충실도 비율은 생성기의 진료 흐름을 반영할 뿐 기대치가 아닙니다.
- **선택 항목 미제출 표시:** 선택 컬럼(원천 코드)·CONCEPT·VOCABULARY 를 내지 않아 건너뛴 규칙은 사유가 '선택 항목 미제출'이며 '미검사 규칙'과 '검사 범위 확인 필요'에 세지 않습니다(1.0.3 에서는 모든 실행이 '검사 범위 확인 필요'로 보였습니다).
- **검증 기준 패키지 1.0.4:** 데이터 충실도 정의 2종(`spec/expected_data.yaml`, `spec/concept_sets.yaml`)이 더해져 9개 파일이며 **앱 1.0.4 이상**이 필요합니다.
