# 바뀐 점

- **이름이 K-AIPA DQ 로 바뀌었습니다.** 앱 이름은 K-AIPA DQ, 한글 설명은 «K-AIPA 임상 데이터 품질검증», 영문은 «K-AIPA Clinical Data Quality Validator»입니다(이전 이름: Quality Validator). 설치 파일 이름은 `K-AIPA-DQ-1.0.0-mac-arm64.dmg`, `K-AIPA-DQ-1.0.0-win-x64.exe`, `K-AIPA-DQ-1.0.0-win-arm64.exe` 입니다. 견본 데이터 이름 `SampleData-1.0.0-*.zip` 은 그대로입니다.
- **새 저장소·소개 페이지.** 소스와 릴리스는 https://github.com/nanumspace/K-AIPA_DQ, 소개 페이지·자료실은 https://nanumspace.github.io/K-AIPA_DQ/ 입니다. 이전 저장소(`nanumspace/KAI_DQ_App`)와 v0.3.x·v0.4.0 릴리스는 그대로 남아 있으며, 이전 주소가 새 주소로 연결된다는 보장은 없습니다. 이 저장소는 이전 저장소의 git 이력을 이어받았습니다.
- **버전 체계.** 1.0.0 은 이름과 배포 위치를 바꾼 첫 릴리스이며 검증 기준과 규칙의 의미는 v0.4.0 과 같습니다: 의뢰사 매뉴얼 2026-11-16 하나(표 16개 · 필드 157개), 규칙 390개(구조 368 + 교차 22). 이전 기준 선택 기능은 되살리지 않았습니다. 이전 기준이 필요하면 v0.3.x 앱을 쓰세요.
- **범위를 분명히 했습니다.** K-AIPA 는 K-AI 신약개발의 전임상·임상 모델개발 사업이며, 이 앱은 그중 **여섯 질환 코호트 임상 테이블의 검증**만 합니다. 전임상·오믹스·AI 모델 검증과 임상 인증은 하지 않으며, 검증 통과는 임상적 적절성이나 기관 승인을 뜻하지 않습니다. K-AIPA 의 공식 승인·후원을 받았다는 뜻도 아닙니다.
- **설치 연속성.** 실행 이력과 규칙 설정이 저장되는 앱 데이터 폴더 이름(`Quality Validator`)은 바꾸지 않고 코드에서 고정했습니다. macOS 에서 v0.4.0 설치의 기록이 새 앱에서도 이어지는 것을 확인했고, Windows 는 같은 제품 이름 기본값에서 추정한 것으로 설치 파일로 시험하지 않았습니다. 새 이름의 설치 파일을 따로 설치하며, 이전 Quality Validator 설치가 있으면 직접 지워야 할 수 있습니다. `submission.json` 의 스키마(`kai-dq-submission/1`)와 규칙 id 는 그대로입니다.
- **가상 임상 사례(Good Sample)와 견본 데이터를 다듬었습니다.** 코호트별 가상 환자 1명의 진단·검사·치료·추적 경과와 표 사이의 연결을 더 일관되게 만들고, 사례마다 가정·참고 근거·한계를 `README.md` 에 적었습니다. 이는 합성한 임상 사례 예시이며 «좋은 임상 표준»이나 진료 지침이 아닙니다. 임상의의 감수·승인을 받지 않았습니다. 규칙은 바꾸지 않았습니다.
  - Good Sample 6종은 위반 0건입니다.
  - clean 견본은 오류 등급 위반이 0건입니다. 다만 대장암(14건)·림프종(7건)에서 임상 치료 차수와 요법 시작일 순서가 달라 생기는 경고 `SEM-SACT-006` 이 남을 수 있습니다. 이 경고는 규칙의 임상 휴리스틱이며 숨기지 않고 그대로 보여 줍니다.
  - dirty 의 오류는 규칙에서 역으로 만든 것이라 «모두 검출»이 실제 병원 데이터에서의 민감도는 아닙니다.
- **문서의 규칙 구분.** 매뉴얼에 적힌 제약(오류), 표 사이 논리(교차 규칙, 오류·경고), 임상 휴리스틱(경고)을 구분해 설명합니다(교차 규칙 22개 중 오류 14 · 경고 8). 규칙의 의미는 바꾸지 않았습니다.
- 소개 페이지와 자료실은 main 에 push 할 때마다가 아니라 공개 릴리스를 기준으로 배포합니다. 릴리스 스크립트는 버전을 올리거나 커밋하지 않고 커밋된 버전만 확인합니다.

### 알려진 한계

- Athena 어휘가 들어 있지 않아 concept_id 의 존재·표준 여부는 검사하지 않습니다(OMOP 코드표는 경고 수준).
- 항종양제 판정(`sact_id` 연결 확인)은 앱에 내장된 항암제 목록을 기준으로 하므로 목록 밖 약제는 잡지 못합니다.
- 림프종 아형(DLBCL 여부)을 담은 열이 명세에 없어, DLBCL 인데 `cell_of_origin` 에 `NA` 를 잘못 적은 경우(또는 그 반대)는 검출하지 못합니다.
- 가상데이터에서의 결과는 실제 병원 데이터에서의 민감도·오탐률을 예측하지 않습니다. 실데이터에서의 동작은 파일럿에서 확인합니다.
- Windows 32비트와 Intel Mac 은 제공하지 않습니다.
